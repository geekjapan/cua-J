# Native decision comparison, 28 October 2026

Verdict: inconclusive for a general performance or accuracy winner. In this bounded AppKit sample, Microsoft Decision-1 and ordinary Responses completed every task. OpenAI Decisions stopped all five counter tasks at a fixed confidence gate or abstention. None of the 45 trials recorded a distractor action. Faster refusal is not a completed-task speedup.

The deliverable is a Python native controller in `examples/jev-use`. Rust Driver, the TypeScript runner and browser provider support remain unchanged. Finite candidates, validation and exact dispatch are deterministic rules. Model selections and external UI behavior are not guaranteed deterministic.

## Setup

- Three native tasks, each repeated five times per provider, give 45 sequential trials. Provider order rotates each round. Every trial starts a fresh AppKit fixture and runner. The daemon uses a private socket and state directories.
- `standard-llm` uses actual OpenAI Responses function calls with `gpt-6-luna`, reasoning `none`. It generates an operation and arguments. The executor requires an exact authorized action match. This is a matched conventional-LLM control on the unchanged Driver, not a measurement of every original upstream agent-SDK example or an unrestricted screenshot agent.
- `openai-decisions` uses `gpt-6-luna` through `/v1/decisions`. `microsoft-decision1` requests the `decision-1` deployment and returns `microsoft-decision-1`. Microsoft and OpenAI are different models.
- Each variant sees the same goal, actual redacted AX text and performed-action history. Benchmark input removes declared-step progress, next-action hints and task-step candidate ranking. The synthetic note is public to all variants. Model requests do not receive the oracle's correctness labels.
- AppKit density is 12. Counter requires three increments. Save-note requires setting the supplied note and saving it. Choose-size requires Large and agreement. Success requires the independent state oracle, zero distractor actions, unchanged density, a verified runner outcome and exit code zero.
- Decision acceptance stays at probability 0.6, margin 0.1 and observation age 30 seconds. The baseline has no fabricated probability. No thresholds changed after seeing failures. The timeout is 120 seconds per trial, HTTP timeout 60 seconds, no retries or redirects, one in-flight trial and a pooled client within each runner.
- macOS 27.0.1 arm64, 14 logical CPUs, Python 3.13.13 and httpx 0.28.1. The same Rust 1.95.0 release Driver and native fixture binaries serve all variants. Start load averages were 15.79, 17.04 and 17.99. Other host work continued; rotation reduces drift but does not remove that noise.

These are observed application completions under the fixed policy, not intrinsic model accuracy. All 45 final state files report zero distractor actions. Unexpected attempts use withheld expected-action labels in the logs, not model inputs. Driver reports the save-note click effect as unverifiable; the independent saved-note state proves the task. Delivery counts remain nullable where an individual effect was not reconciled. They are not silently promoted to confirmed deliveries.

All recorded requests include input/output usage. OpenAI Decisions reports zero output tokens; this is the provider field, not an estimate that inference is free. Microsoft omits total, cached and reasoning token fields; those stay null. Trials have different completion lengths, so aggregate token totals are not a per-success cost comparison. No monetary price or cost claim is made.

## Failures and limits

All five non-completions are OpenAI Decisions counter trials. Four selected the correct Increment candidate at the third step, with probabilities 0.55, 0.50, 0.41 and 0.52, and were withheld by the 0.6 probability gate. The fifth abstained after two increments. They are four policy rejections and one abstention, not five misclicks. There were no recorded HTTP/parse failures, timeouts or action errors in this matrix. Raw all-trial wall times, including failures, remain in the JSON and are not presented as successful latency.

The APIs' probability calibration is not assumed equivalent. A three-task synthetic sample cannot establish general desktop accuracy. This does not measure arbitrary text generation, visual grounding, menus, browser flows, other operating systems or long-horizon planning. Reusing capture IDs and tokens does not prove that an external app stayed unchanged during inference. Failed trials remain visible, and no global winner is selected.

## Where the time goes

A separate cProfile run made one real request per provider on a previously captured static fixture. Each selected Increment. SSL socket reads dominated the call, while process CPU was small. This local profile identifies waiting on the remote response path; it does not separate server processing from network latency. It is excluded from the 45 timed trials and cannot establish a provider speed ranking. Sanitized profile counters are in the JSON.

Across the completed baseline tasks, inference accounts for 20.4% of total end-to-end time and AX observation for 46.6%. These shares explain why a much shorter model call cannot deliver the same multiple in whole-task speed. Oracle polling and native action time remain. Task-level ranges overlap in several comparisons, and the host was busy. End-to-end differences cannot be attributed solely to model inference.
